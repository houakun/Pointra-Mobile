# Pointra Mobile — 需求与架构设计

> 配套项目：`Pointra-Pub`（Tauri v2 桌面光标翻译工具）
> 文档版本：**v2（已应用确认轮 1 + 确认轮 2 的全部决策）**
> 仓库名、App 名、包名为占位，待 Q8 确认后可一键改名

## 1. 需求概述

在 Pointra 桌面端查词（光标取词 / 选词翻译）时，通过**手动触发**把当前查询结果**即时推送**到同一局域网内的 Android App；
Android App 以「不背单词」式卡片承载**单词**与**句子**，使用简化 SM-2 间隔重复算法安排复习。

### 2.1 设计要点

- **PC 端是唯一数据源（source of truth）**。手机丢失/重装后可从 PC **全量重拉**（对应 E18 无云备份）。
- **手机端不出网**（音频除外），几万词义本地 SQLite，翻卡零延迟。
- **无反向同步**（A4）使协议保持**单向只增**，冲突问题彻底消失。
- **PC 端不做词库管理 UI**（Q4）：只在设置页展示配对信息与只读计数，用于确认收藏生效。

### 2.2 已知限制（诚实标注）

| 限制 | 说明 |
|---|---|
| 手机端本地删除的词，**重装后会随全量拉取回来** | 单向同步的必然结果；因为 A4 选择了无反向同步 |
| WS 只在前台有效 | 满足 Q3；后台不推送，靠「打开即补齐」 |
| 模拟器开发 ≠ 真机同 WiFi | 见 §4.6 |
| 有道 `dictvoice` 只服务**词库收录的词/短语**，不是任意文本的 TTS | 实测 `practice makes perfect`、`how are you today` 返回 `200 audio/mpeg`；而 `this is a test`、`asdf qwer zxcv` 返回 `500 application/json`。因此**单词卡发音必定可用**，句子卡发音仅对有道收录的句子生效（Q15 的整句 TTS 建立在免费接口上，这是它的真实边界） |

## 3. 数据模型

### 3.1 PC 端 `vocab.db`（SQLite，位于 `app_data_dir`）

```sql
-- 全局同步序号分配器：words / sentences 共用同一个序列。
-- 手机端只维护一个 last_seq 游标；若两表各自 AUTOINCREMENT，
-- 会产生重复的 seq，用全局 max 当 since 就会漏数据。
CREATE TABLE seq_counter (
    id    INTEGER PRIMARY KEY CHECK (id = 1),
    value INTEGER NOT NULL
);
INSERT OR IGNORE INTO seq_counter (id, value) VALUES (1, 0);

-- 单词
CREATE TABLE words (
    seq          INTEGER PRIMARY KEY,     -- 取自 seq_counter，全局唯一且单调递增
    id           TEXT    NOT NULL UNIQUE,           -- sha1(lower(trim(word)))
    word         TEXT    NOT NULL,                  -- 原词（保留大小写）
    normalized   TEXT    NOT NULL,                  -- lower(trim(word))
    phonetic_us  TEXT,                              -- 美音标
    phonetic_uk  TEXT,                              -- 英音标
    audio_us     TEXT,                              -- 美音 URL
    audio_uk     TEXT,                              -- 英音 URL
    dit          TEXT,                              -- 中文释义（translate.dit）
    usual_dict   TEXT,                              -- JSON: [{pos, values:[]}]
    exchange     TEXT,                              -- JSON: {word_past:[], word_pl:[], ...}
    added_at     INTEGER NOT NULL,
    updated_at   INTEGER NOT NULL
);

-- 句子
CREATE TABLE sentences (
    seq       INTEGER PRIMARY KEY,       -- 与 words 同一个序列
    id        TEXT    NOT NULL UNIQUE,   -- sha1(trim(text).lower())
    text      TEXT    NOT NULL,          -- 英文原句
    trans     TEXT,                      -- 中文译文
    added_at  INTEGER NOT NULL
);

CREATE TABLE meta (k TEXT PRIMARY KEY, v TEXT);
```

**去重规则（Q5）**：`id = sha1(normalized)`，重复收藏执行
`INSERT ... ON CONFLICT(id) DO UPDATE SET dit=?, usual_dict=?, ... , updated_at=?`
——**`seq` 保持不变**（否则手机端增量游标会错乱），只更新词义并推送 `word.updated`。
手机端收到 `updated` 时**只更新词义字段，不动 `state/ease/interval/reps/due_at`**。

### 3.2 Android 端 SQLite

在 PC 结构上追加学习状态列（单词与句子**各自独立**维护复习进度）：

```sql
CREATE TABLE words (
    seq INTEGER PRIMARY KEY, id TEXT NOT NULL UNIQUE,
    word TEXT NOT NULL, normalized TEXT NOT NULL,
    phonetic_us TEXT, phonetic_uk TEXT,
    audio_us TEXT, audio_uk TEXT,
    dit TEXT, usual_dict TEXT, exchange TEXT, added_at INTEGER,
    -- ==== 学习状态（SM-2）====
    state       INTEGER NOT NULL DEFAULT 0, -- 0=新 1=学习中 2=复习中 3=已掌握
    ease        REAL    NOT NULL DEFAULT 2.5,
    interval    INTEGER NOT NULL DEFAULT 0, -- 天
    reps        INTEGER NOT NULL DEFAULT 0,
    lapses      INTEGER NOT NULL DEFAULT 0,
    due_at      INTEGER,                    -- 到期时间戳；NULL=未安排
    first_seen  INTEGER,                    -- 首次进入学习（用于"今日新词"计数）
    last_review INTEGER
);
CREATE INDEX idx_words_due   ON words(state, due_at);
CREATE INDEX idx_words_norm  ON words(normalized);

CREATE TABLE sentences (
    seq INTEGER PRIMARY KEY, id TEXT NOT NULL UNIQUE,
    text TEXT NOT NULL, trans TEXT, added_at INTEGER,
    state INTEGER NOT NULL DEFAULT 0, ease REAL NOT NULL DEFAULT 2.5,
    interval INTEGER NOT NULL DEFAULT 0, reps INTEGER NOT NULL DEFAULT 0,
    lapses INTEGER NOT NULL DEFAULT 0, due_at INTEGER,
    first_seen INTEGER, last_review INTEGER
);
CREATE INDEX idx_sent_due ON sentences(state, due_at);

CREATE TABLE daily_stats (
    day         TEXT PRIMARY KEY,   -- 'YYYY-MM-DD'（以 04:00 为日界）
    new_done    INTEGER DEFAULT 0,  -- 今日已学新词（单词 + 句子合计）
    review_done INTEGER DEFAULT 0,  -- 今日已复习（单词 + 句子合计）
    study_ms    INTEGER DEFAULT 0   -- 今日学习时长（学习页前台计时累计）
);

CREATE TABLE sync_state (k TEXT PRIMARY KEY, v TEXT);
-- last_seq / server_host / server_port / token / server_device_id
```

## 4. 同步协议

### 4.1 传输层

- 明文 **HTTP/1.1 + WebSocket**，端口默认 `31415`（设置页可改）。
- 认证：`Authorization: Bearer <token>`（`/api/ping` 与 `/api/pair` 除外）。
- ⚠️ **Android 必须放行明文流量**：`AndroidManifest.xml` 的 `application` 上加
  `android:usesCleartextTraffic="true"`，或配置 `network_security_config` 仅放行局域网网段。

### 4.2 配对

PC 端「设置 → 手机同步」页展示：

```
本机地址: http://192.168.1.23:31415
配对码:   482913        ← 6 位数字，5 分钟有效，一次性
[二维码]                ← pointra://pair?host=192.168.1.23&port=31415&code=482913
```

手机端提供**两种**配对方式（手输为兜底）：
1. 手动填 IP + 端口 + 6 位配对码 ← **必做**
2. 扫码（`tauri-plugin-barcode-scanner`）← 可选，插件在 Android 上不稳定则跳过

### 4.3 接口

| 方法 | 路径 | 鉴权 | 说明 |
|------|------|------|------|
| GET | `/api/ping` | 否 | `{name, version, device_id, paired}`，用于地址探活 |
| POST | `/api/pair` | 否 | `{code, device_name}` → `{token, device_id}` |
| GET | `/api/words?since=<seq>&limit=500` | 是 | `{items:[...], next_since, has_more}` |
| GET | `/api/sentences?since=<seq>&limit=500` | 是 | 同上 |
| GET | `/api/stats` | 是 | `{word_count, sentence_count, last_seq}` |
| WS | `/api/events?token=<token>` | 是 | 推送 `{"type":"word.added"\|"word.updated"\|"sentence.added","seq":N,"payload":{...}}` |

**增量语义**：`since` = 已落库的最大 `seq`（不含），返回 `seq > since` 升序记录；
手机端每批成功后 `last_seq = max(seq)`。分页 `limit=500`，几万词约 40–100 次请求，配合进度条。

### 4.4 「即时推送」的真实边界

Android 会冻结后台进程，**WebSocket 只在前台/可见期有效**。这与 Q3 的决策一致：

| 场景 | 表现 |
|------|------|
| App 在前台 | WS 长连接；收到 `word.added` 立即入库并轻提示「+1 个生词」 |
| App 退到后台 / 被杀 | WS 断开（PC 端 30s 心跳超时后清理连接） |
| 再次打开 App | `GET /api/words?since=last_seq` **增量补拉**，秒级补齐 |
| 断网恢复 | WS 指数退避重连（1s→2s→4s…上限 30s），重连成功后补拉 |

> **结论：不再实现 Android 前台服务（P7 取消）。** 用户可见效果 = 「翻译完，手机一打开词就在里面」。

### 4.5 断线排队

PC 端不关心手机是否在线：所有词先落 `vocab.db`（`seq` 递增），有 WS 连接就推，没有就等手机端补拉。
**PC 端无需任何队列** —— 这是「服务端持有全量数据」带来的最大简化。

### 4.6 模拟器网络（Q12 相关）

| 目标 | 手机端填写的地址 |
|------|------------------|
| Windows 上的 **AVD 模拟器** 访问宿主机 PC | **`10.0.2.2:31415`**（模拟器专用的宿主机回环别名） |
| **真机** 通过同一 WiFi 访问 PC | PC 的局域网 IP，如 `192.168.1.23:31415` |

PC 端服务固定监听 `0.0.0.0:31415`，两种方式都通。手机端设置页**地址可编辑**，随时切换。

## 6. Android 端设计

### 6.1 工程形态

独立仓库（F24），Tauri v2 纯 mobile 项目：

```
Pointra-Mobile/
├── src/                        # React 前端（pages / components / store / db bridge）
├── src-tauri/
│   ├── src/                    # Rust：sqlite 访问、同步客户端、SM-2 计算
│   ├── Cargo.toml
│   ├── tauri.conf.json
│   └── gen/android/            # tauri android init 生成
├── package.json
└── docs/
```

插件（Android 可用性在 P0/P3 验证）：`tauri-plugin-sql`、`tauri-plugin-store`、`tauri-plugin-os`、`tauri-plugin-process`；可选 `tauri-plugin-barcode-scanner`。

### 6.2 页面与交互

**① 今日页**（对齐截图顶部统计栏）

```
┌────────────────────────────────────────┐
│  今日复习      今日新词      学习时间   │
│  12/100        5/20          28min     │
├────────────────────────────────────────┤
│            [ 开始学习 ]                │
│     待复习 88 · 未学 1240              │
│     句子：待复习 6 · 未学 40           │
└────────────────────────────────────────┘
```
分母 = `min(到期总数, 每日上限)`；「学习时间」= 学习页前台停留毫秒累计。

**② 学习页**（不背单词式；单词卡与句子卡**共用同一队列**）

两个状态互斥：

**A. 正面（未看答案）—— 空白处不解锁，避免误触**
```
              scout
          /skaʊt/  🔊
    想不起来就点下方「不认识」查看释义

  [  不认识  ]    [  我认识  ]
  [      标记为太简单      ]
```
**B. 看过释义后 —— 三档按钮隐藏，只留「下一个」**
```
              scout
          /skaʊt/  🔊
        ┌ 词性标签 ┐
        n.  [侦察员] [童子军]

  [        下一个        ]
```
句子卡同理：正面是英文原句（默认「英 → 中」回想），展开后是中文译文。

- 顶部细进度条显示本次队列进度。
- 音标/发音按设置中的美/英偏好；🔊 播放 `audio_us/uk`（单词）或有道整句 TTS（句子）。
- 交互：
  - **「不认识」** → 记 Again（当日回队尾）并**展开释义/译文**；停在本卡，按钮换成「下一个」。
  - **「我认识」/「标记为太简单」** → 直接切到下一张（不展开）。
  - **「下一个」** → 前进；这张卡已记过 Again，会被挪到本次队列尾部。
- 「标记为太简单」→ `state=3`，`due_at = now + 365d`，移出队列。
- 为什么「不认识」的出队时间不放在点击那一刻：那样卡一翻开就换页，释义根本来不及看。

**③ 句子本**（Q9：也要卡片复习）
- 列表视图：原句 + 译文 + 复习状态徽标（未学/学习中/复习中/已掌握）+ 到期时间
- 搜索（按原句/译文关键词）+ 状态筛选
- 本地删除（单条）
- 句子卡与单词卡**共用 §6.2② 的卡片组件**，仅正面内容与发音方式不同

**④ 词库页**（几万词）
- 分页加载 + 虚拟滚动（WebView 禁不起几万 DOM 节点；行高固定 64px，只渲染视口附近的行）
- SQL 前缀索引搜索（`normalized` 半开区间 + `EXPLAIN QUERY PLAN` 验证走 `idx_words_norm`）
- 筛选：状态（未学/学习中/复习/已掌握）、首字母 A–Z
- **按加入日期搜索**：日期选择器选**本地日历日** → `added_at` 落在 `[当日 00:00, 次日 00:00)` 毫秒区间；
  与搜索/状态是「与」关系；旁边「清除」一键取消
- **排序**：右上角在「按字母 A-Z」与「按加入时间 ↓」之间切换（后者 `added_at DESC, seq DESC`）
- 列表每行显示 `释义 · 加入日期`，筛选结果可肉眼核对

**⑤ 设置页**
- 服务器：地址（默认 `10.0.2.2`）、端口、配对码、配对状态、重新配对/解绑
- 每日目标：新词上限（默认 20）、复习上限（默认 100）
- 发音：美/英、查词后自动发音开关
- 数据：同步状态（last_seq / 本地词数 / 服务端词数对比）、**清空本地数据并重新全量同步**

**⑥ 速记页**（今日页「速记」入口：纯单词快速过一遍）
```
返回            速记            50 词
apple       n. 苹果；苹果公司；
            n. 苹果树；苹果状物
banana
cherry
...
   上下滚动浏览 · 点单词看释义 · 向左滑动＝标记太简单
```
- 单词与学习页**同源**（`build_queue`：到期复习 ++ 新词，受每日上限约束），只取 `kind = word`
- **点单词** → 在该行**右侧**就地展开常见释义（`usual_dict` 按词性分行；取不到退回 `dit`）。
  **释义会一直留着**：可以同时展开多张，互不影响；再点同一个词才收起（`expanded` 用数组而不是单个 id）。
  只有**左滑清除**才会让释义跟着行一起消失。
- **向左滑动** → **等同「标记为太简单」**：先写回学习进度（`state=3`、`interval=365`、不再入队），
  成功后再从速记列表滑出；写库失败会提示且**不移除**（避免「界面清掉了但没落库」）。
  因此队列条目（`QueueEntry`）新增 `state` 字段，前端据此决定这一笔计「今日新词」还是「今日复习」，
  不必为了拿状态再多跑一次 `get_card`。
- **上下滚动**：**原生连续滚动**（`overflow-y: auto` + `touch-action: pan-y`），不是一页一页硬翻；
  只放行竖直方向，横向留给「左滑＝太简单」
- 布局坑（踩过）：`.memo-body` 若是 column flex 容器，子项默认 `flex-shrink: 1`，
  几十行会被压扁到几十像素，再被 `overflow: hidden` 裁掉文字，看起来像一排空行 ——
  行必须 `flex: none`（现改为 `display: block` + `flex: none` 双保险）
- 手势判定：竖直方向交给浏览器原生滚动（浏览器接管时会发 `pointercancel`，此时**只收尾、不当点按**），
  横向才由 JS 驱动；点按在 `pointerup` 里判（不用额外 `onClick`，否则拖完会误触）

### 6.3 学习队列生成

```
today = 以 04:00 为界的当日

到期队列 = 单词: (state IN (1,2) AND due_at <= now)  按 due_at 升序
        ∪ 句子: (state IN (1,2) AND due_at <= now)  按 due_at 升序
        → 合并后按 due_at 升序，取前 min(总数, 每日复习上限)

新词队列 = 单词: state = 0  按 seq 升序
        ∪ 句子: state = 0  按 seq 升序
        → 合并后按 seq 升序，取前 min(总数, 每日新词上限)

本次队列 = 到期队列 ++ 新词队列
```
- 每日目标**单词与句子合计计数**（保持截图「今日复习 / 今日新词」三项统计的简洁），不做分栏。
- 「不认识」的卡片插入**本次队列尾部**（当日再来）。计数按**每次评分实时累加**：
  首评计入「今日新词」（当时 `state=0`）或「今日复习」；回队尾后再评一次会计入「今日复习」，
  所以同一张卡当日可能同时出现在新词与复习两项里（P4 实测 new_done=3 / review_done=1）。
- 队列耗尽 → 结束页，写入 `daily_stats`。

## 7. 复习算法（SM-2 简化）

三档评分映射（关键词 / 句子卡共用同一套逻辑）：

| 交互 | SM-2 quality `q` | 附加 |
|------|------------------|------|
| 不认识 | 2 | `lapses += 1` |
| 我认识 | 4 | — |
| 标记为太简单 | 5 | `state = 3`，`interval = 365`，永不再入队 |

更新规则：

```
if q < 3:
    reps = 0
    interval = 0          // 当日回队尾重来
    state = 1
else:
    if reps == 0:      interval = 1
    elif reps == 1:    interval = 6
    else:              interval = round(interval * ease)
    reps += 1
    state = 2
    if interval >= 180: state = 3      // 毕业

ease = ease + (0.1 - (5 - q) * (0.08 + (5 - q) * 0.02))
if ease < 1.3: ease = 1.3

due_at      = 当日04:00 + interval 天    // 统一日界，避免"睡前复习、白天又出现"
first_seen  = 若为空则置 now
last_review = now
```

> **ease 只在「不认识」时下降**：`q=4` 时 `ΔEF = 0.1 - 1×(0.08 + 0.02) = 0`；
> `q=2` 时 `ΔEF = 0.1 - 3×(0.08 + 0.06) = -0.32`。
> 这是有意简化：两档按钮下，保证「一直认识」的词间隔稳定增长而不被 ease 惩罚。

### 实现过程中修正的设计缺陷

**`seq` 必须全局唯一（原设计有 bug）**

原设计让 `words.seq` 与 `sentences.seq` 各自 `AUTOINCREMENT`。实测发现两表的
第一条记录**都会拿到 `seq = 1`**：

```
words:     A(1)              C(2)
sentences:      B(1)                  D(2)
last_seq = max(2, 2) = 2
→ 手机端用 since=2 拉 sentences 会永久漏掉 B(1)
```

修正为 `seq_counter` 单表分配全局序号，并补了回归测试 `seq_is_global_across_tables`。
